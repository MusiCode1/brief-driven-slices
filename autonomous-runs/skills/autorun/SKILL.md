# autorun — סבב אוטונומי אחד

> **אל תעתיק לכאן תבניות.** הן חיות ב-`autonomous-runs/` ומתוחזקות שם.
> העתקה יוצרת drift — ריפו-השיטה אוסר זאת במפורש (דוקטרינת env).

## הזרימה

```
1. תור      →  cd <project>/docs-for-llm/plans && ./backlog-status.sh
2. בחירה    →  המשתמש, או הראשון הפתוח
3. טרום     →  חמש הבדיקות למטה  ← הערך של הסקיל
4. משימה    →  מ-MISSION_TEMPLATE.md, JIT, commit ל-docs-repo
5. ענף      →  integration/run-<שם>, מעל הבסיס שנקבע ב-3
6. שיגור    →  **API** (‏למטה) · prompts/kickoff-mordechai.md
7. סגירה    →  דוח-ריצה + שורה בפנקס + **סגירת כל סשן שנפתח**   ← אל תדלג
```

## 🔴 3 — חמש בדיקות-הטרום

**כל אחת מהן נכשלה פעם אחת ועלתה זמן.** לענות עליהן *לפני* כתיבת המשימה.

| # | הבדיקה | איך בודקים |
|---|---|---|
| 1 | **הבסיס נכון?** הקוד שהסלייס נוגע בו קיים שם? | `git -C <repo> show <base>:<path>` |
| 2 | **השער בר-הרצה?** | סף/טיימר/תנאי — האם המאמת יכול להפעילו בשניות? אם לא, **הוספת ה-knob היא חלק מהסלייס** |
| 3 | **תלות-קשת?** | `roadmap.md` §הקשתות — תרשים-התלויות קובע מאיפה מסתעפים |
| 4 | **מה ה-DoD *אינו* טוען?** | שורש-מאומת-בקוד ≠ שורש-מוכח. לרשום במפורש |
| 5 | **נתיב-דוחות יחיד מוצהר?** | `$BDS_REPORTS/<project>/` — ולוודא שאין דוח מחוץ לו |
| 6 | 🔴 **מי מריץ את מי?** | ‏ברירת-המחדל מאז 28/08 ‏היא **‏ה-API** (§‏שיגור דרך ה-API). ‏לצטט בגוף השיגור את **הפקודה עצמה**. ‏אליעזר+כלב = cursor · ‏מרדכי+אביגיל+כלב-heavy = ‏Claude ב-process. ‏מסלול tmux (`dispatch-agent <שם> cursor composer-2.5 <cwd> <prompt>`, ‏`composer-2.5` **‏בלי קידומת**) ‏נשאר כנפילה-לאחור |

> **הרציונל של #6:** ‏הכלל כתוב ב-4 ‏מסמכים מאז 20/08, ‏והמשתמש נאלץ למסור אותו
> ‏שוב בריצה 6 ‏**‏ובריצה 15**. ‏השורש אינו שכחה: ‏`agents/eliezer.md` ‏עצמו הציג
> ‏את מסלול-ה-`Task` ‏כ"‏Mode 1". ‏מאז 25/08 ‏יש שם **‏שער בר-כישלון** —
> ‏`BDS_SLICE` ‏לא-מוגדר ⇒ ‏הסוכן מחזיר `WRONG-DISPATCH` ‏ומסרב לבצע.
> ‏הבדיקה הזו היא ה**‏חגורה**; ‏השער הוא ה**‏כתפיות**.

> **הרציונל של #2:** בריצה 1 סוויטה של 30/30 ירוקים אישרה קוד ששבר 100%
> מחיבורי ה-HTTP — כל טסט הזריק מוק ואיש לא הריץ את ברירת-המחדל.
> **שער שאי אפשר להריץ אינו שער.**

## 🔴 ‏שיגור דרך ה-API — ‏ברירת-המחדל מאז 28/08

‏למה זה עדיף על tmux: ‏הסוכן **‏מופיע ברשימה, ‏יש לו URL, ‏ורואים אותו רץ מהטלפון**;
‏אות-הסיום הוא `stopReason` ‏בזרם ‏ולא קוד-יציאה של תהליך (‏שמשקר — ‏פער 2);
‏והסגירה אוטומטית בהצלחה.

### ‏שלב 0 · ‏מה **‏המזהה שלי**

‏בלי זה אין למי לדווח, ‏ותחזור לסקירת-זרם. ‏סוכן שרץ **‏בתוך** drive-coding
‏מגלה את עצמו מעץ-התהליכים:

```bash
ps -o ppid=,args= -p $$          # ‏לטפס עד: bun …/bin/drive-coding.ts
curl -s 127.0.0.1:<port>/api/agents   # ‏להתאים לפי cliKind + cwd
```

⚠️ ‏לסוכן claude ‏בגשר ה-in-process ‏השדה `pid` ‏הוא **`null`** — ‏אל תפסול אותו בגלל זה.
‏אימות: ‏ה-`sessionId` ‏שווה לשם קובץ-הטרנסקריפט.

### ‏שני שלבים

```bash
# ‏1 · ‏פתיחה. --parent ‏מזריק DC_PARENT+DC_BASE ⇒ ‏הילד ידווח לך בסיום
scripts/dispatch-via-api.mjs open --base http://127.0.0.1:4001 \
  --cli cursor --cwd <worktree> --env BDS_SLICE=<‏סלייס> \
  --permission allow_once --parent <‏המזהה שלך> \
  --public-url https://drive-coding-dev-vps.musicode.ovh --json

# ‏2 · ‏משימה. --no-wait ‏כשיש --parent: ‏ההודעה תגיע, ‏אין צורך לשבת על הזרם
scripts/dispatch-via-api.mjs send --agent <id> --prompt-file <f> --no-wait
```

‏בגוף הפרומפט לילד — ‏להנחות אותו לשלוח `notify` ‏בסיום (‏הסעיף כבר קיים
‏ב-`agents/eliezer.md` · `avigail.md` · `calev*.md`).

### ‏קודי-היציאה של `send` ‏(‏כשממתינים)

| ‏קוד | ‏משמעות | ‏מה לעשות |
|---|---|---|
| 0 | ‏הסתיים | ‏הסוכן נסגר לבד |
| 2 | ‏פג-זמן | ‏אינו כישלון — ‏קרא שוב |
| 3 | **‏הזרם נסגר בלבד** | ‏נמדד 27/08 ‏שהסוכן **‏המשיך לעבוד**. ‏בדוק `/state`; ‏חי ⇒ ‏`await-api.mjs` ‏להתחברות מחדש. **‏אל תשגר המשך** |
| 5 | ‏שקט — ‏תקוע | ‏אסוף ראיה, ‏ואז `close` |

### ‏שלוש מלכודות שנמדדו

- **‏אל תרים שרת על 4000/4001** — ‏שם פריסות חיות.
- ‏קוד-יציאה נמדד **‏בלי צינור**. `cmd | tail` ‏מחזיר את הקוד של `tail`.
- ‏משתני-סביבה של הפריסה (`PORT` · `FE_ENV` · `FE_STATIC_DIR`) ‏**‏דולפים** ‏לסוכנים.
  ‏לנקות לפני מדידה.

## 6 — ארבע האזהרות בשיגור

לכלול בגוף ה-dispatch, לא להסתמך על הזיכרון של הסוכן:

1. **שיגור ברקע, אחד-אחד** (`run_in_background: true`) — **הופך את הכלל הישן**
   (`SKILL.md §שיגור לא-חוסם`). השרשור הראשי נשאר פנוי למשתמש; מעקב בראיות-עץ,
   לא בהמתנה חוסמת. הלקח מריצה 1 שנשאר: אחרי שיגור לא נעלמים.
2. **`stat` לפני כל verdict** + חיפוש דוח נוסף בנתיב אחר.
3. **מיזוג לענף-ההרצה אוטונומי; החוצה — המשתמש בלבד.**
4. **חובת-ראיה:** כל טענת-סטטוס עם הפקודה שהפיקה אותה והפלט.

## 7 — הסגירה (החלק שמדלגים עליו)

```
דוח   →  runs/<תאריך>-<שם>.md  מ-RUN_REPORT_TEMPLATE.md
פנקס  →  שורה ב-README.md: התערבויות מוצר/צנרת · כשלי-מסירה · תיקונים
סשנים →  scripts/dispatch-via-api.mjs close --agent <id>   ‏לכל id ‏שנפתח בסבב
```

🔴 **‏חובת-הסוגר.** ‏הסקריפט סוגר לבד **‏רק בקוד 0**; ‏בכל קוד אחר הוא משאיר את
‏הסוכן חי **‏במכוון** — ‏הוא הראיה — ‏ולכן הסגירה שלך, ‏אחרי האיסוף. ‏במסלול tmux
‏אין סגירה אוטומטית כלל. ‏הדוח מכיל טבלת **"‏סשנים שנפתחו ונסגרו"**; ‏שורה ריקה
‏שם היא חזקת-יתום (‏פער 7). ‏סגור **‏רק id ‏שפתחת** — ‏על המכונה חיים סוכנים אחרים.

**סווג כל התערבות ל-מוצר מול צנרת.** רק הצנרת אמורה לרדת בין ריצות — זה
כל מדד-הבשלות. דוח שלא ייצר תיקון קבוע הוא תיעוד, לא ניסוי.
