# autonomous-runs/ — הניסוי: ריצה אוטונומית מקצה-לקצה

**השאלה שהתיקייה הזו בודקת:** האם אפשר למסור למרדכי **מסמך אחד**, ולקבל
בחזרה קוד מוזג — בלי שהמשתמש ינהל את הדרך.

זה **ניסוי**, לא שיטה בשלה. כל ריצה מייצרת דוח על **עצמה**, התיקונים נכנסים
לתבניות, והריצה הבאה נמדדת שוב. כשהתיקונים מתכנסים לאפס — היא בשלה.

---

## במה זה שונה מהתיקיות הקיימות

הבחנה חדה, כי כולן נראות דומות ואינן:

| תיקייה | השאלה שהיא עונה עליה | תדירות |
|---|---|---|
| `reports/<project>/` | האם **הסלייס** תקין? (אביגיל/כלב, פר-סלייס) | כל סלייס |
| `distillations/` | אילו **טעויות-תוכן** חוזרות בכל הפרויקטים? | תקופתי |
| `case-studies/` | מה בדיוק קרה ב**כשל מסוים** ששווה ללמוד ממנו? | לפי צורך |
| **`autonomous-runs/runs/`** | **האם ה*ריצה* עצמה עבדה?** מסירות, שערים, התערבויות | **כל ריצה** |

הדוחות הקיימים הם אימות-**תוכן**. הדוח כאן הוא אימות-**מכניקה**: לא "האם הקוד
נכון" אלא "האם המערכת שמייצרת אותו החזיקה, ואיפה היא דלפה אל המשתמש".


## מדד-הבשלות — כדי ש"התיקונים פוחתים" יהיה מספר ולא תחושה

כל דוח-ריצה מחויב לשתי ספירות:

- **התערבויות-משתמש**, מסווגות ל-**מוצר** (‏scope, ‏עיצוב, ‏אישור-שער — *לגיטימיות, לא נעלמות*)
  מול **צנרת** (‏המערכת לא החזיקה — *אלה שאמורות להתאפס*).
- **כשלי-מסירה** — כל מקרה שבו סוכן פעל על מיָצג שגוי של המציאות.

## איך מריצים סבב

1. המשתמש ממלא `MISSION_TEMPLATE.md` → הקובץ נשמר בריפו-**הפרויקט** (ליד הבריפים), לא כאן.
2. שיגור לפי `prompts/kickoff-mordechai.md`.
3. מרדכי רץ עד שער-המשתמש.
4. **בסוף:** דוח לפי `RUN_REPORT_TEMPLATE.md` → `runs/`, ושורה בפנקס למעלה.
5. כל תיקון-צנרת נכנס ל**תבנית או לסוכן** — לא נשאר בדוח בלבד. דוח שלא ייצר תיקון
   הוא תיעוד, לא ניסוי.
