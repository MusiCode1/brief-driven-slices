## 3. הספייק — מה שההרצה תפסה ושישה סבבי קריאה לא

~420 שורות קוד, ~40 דקות. שלושת האזורים שייצרו חוסמים חוזרים.

1. **`const` ברמה העליונה אינו נוחת על אובייקט ה-context של `vm`** — רק
   `var` והצהרות `function`. נמדד:
   ```
   vm.runInContext("const A=1; let B=2; var C=3; function D(){}", ctx)
     ctx.A → undefined   ctx.B → undefined   ctx.C → number   ctx.D → function
   ```
   27 מ-36 הסמלים הדרושים היו `const`. נדרש אפילוג `this.X = X` מפורש.
2. **`location.protocol` נדרש** — רישום ה-service worker בודק אותו.
   התגלה בהרצה השנייה. שום קריאה לא הייתה מגיעה לזה.
3. **הזהב לא היה דטרמיניסטי.** `JSON.stringify` משמיט מפתחות שערכם
   `undefined`, ולכן `{txt, hit: undefined}` חוזר מהקובץ כ-`{txt}`.
   הרצה שנייה **על קוד זהה** דיווחה על הפרש. תוקן בסבב JSON לפני כל השוואה.
   → זה היה מייצר בדיוק את התרחיש ש-§7 מגדיר כעצירה ("הזהב זז ואינך יודע
   למה") בקומיט הראשון, על קוד תקין.
4. **שומר ההצבה אינו יכול לכלול ספרות.** `parseLine("A: 2x+3y=16").L`
   מחזיר `"2x+3y"` — כפל משתמע.
   ```
   אותיות בלבד  [A-Za-z]    → 2(1)+3(0)-16    0 הפרשים מתוך 180
   +ספרות       [A-Za-z0-9] → 2x+3y-16       87 הפרשים מתוך 180
   ```
   זהו `AGENTS.md` פריט 5 של הפרויקט **שנשך בפעם השנייה**.
   → **מלכודת מתועדת אינה מלכודת סגורה כל עוד אין בדיקה שמריצה אותה.**

## 4. נתיב ההערכה הניטרלי-מנוע — שלוש גרסאות, שתיים שגויות

הבעיה: `coeffs` ו-`numberFormsTeX` קוראים ל-nerdamer ישירות → תחת
compute-engine מחזירים `null` **בשקט**.

- **גרסה 1 (r4): `makeFn` מ-core/numeric.js.** שגויה.
  ```
  makeFn("2*x+3") → ok      makeFn("sqrt(4)*x") → null
  makeFn("x/3")   → ok      makeFn("abs(x)+1")  → null
  ```
  שומר `/[a-zA-Z]{2,}\s*\(/` פוסל כל קריאת פונקציה רב-אותית.
- **גרסה 2 (r5): `expand` + פענוח רציונלי, בלי שומרי NaN.** גרועה יותר.
  `expand` מחזיר `null` בכשל, ו-`Number(null) === 0`. **0 הוא מקדם חוקי** —
  `Number.isFinite` מאשר. נמדד: 34 מתוך 155 מחרוזות בקורפוס.
- **גרסה 3: `subst` (הקיים ב-analyze.js) + `expand` + `numOf` עם שני שומרי NaN.**
  ```
  coeffs — 180 ביטויים · זהה תו-בתו ל-nerdamer: 180 · הפרשים: 0
  compute-engine: coeffs("2x+3y-16") → [2,3,-16]   (היה null)
                  coeffs("1/x")      → null        (ולא מקדם בדוי)
  ```

**ההבדל בין השלוש אינו נראה בקריאה. רק בהרצה.**

## 6. הזהב הקפיא קבוע — ו-`--distinct` תפס

הבריף אמר במפורש: **אל תכניס את `nextStep` לזהב בקומיט 1**, כי הוא
נסגר על `eqs`/`steps` — מערכים ריקים בתוך ה-vm. כשכתבתי את הרתמה
הכנסתי אותו בכל זאת.

```
50 מקרים בקורפוס · ערך אחד: "כתוב קודם משוואה."
--distinct nextStep → 1
```

**קבוע, לא התנהגות.** אחרי התיקון: `--distinct nextStep → 18`.

### תכנון `--regen <key>` — והשומר שהוא כל העניין

צריך היה דרך לתקן ערך שהוקפא **לא נכון מלכתחילה**, בלי לפתוח דלת אחורית.
הפתרון: `--regen` מסרב לכתוב אם ולו מפתח אחד **מחוץ** ל-`<key>` נבדל.

```
$ node scripts/golden-page.js --regen locate
✗ --regen locate מסרב: 66 מפתחות מחוץ ל-locate נבדלים.

$ node scripts/golden-page.js --regen nextStep
✓ חודשו 66 ערכים, כולם תחת nextStep.
```

הוכחתי את הסירוב **לפני** שהשתמשתי בהצלחה. זו התבנית: כלי שיכול לכתוב
על שער חייב להוכיח שהוא מסרב, לא רק שהוא מצליח.

ארבעת המצבים שהתגבשו: `(ללא)` השוואה · `--write` (רק בהקמה) ·
`--add` (הוספה בלבד, מסרב לשנות קיים) · `--distinct <key>` (סופר ערכים
שונים, נופל מתחת ל-3) · `--regen <key>` (מחדש רק תחת מפתח מוצהר).

### א-סימטריית העלות — הנימוק שמכריע

```

ספייק:      ~40 דקות      →  מפיק קוד שנדרש ממילא
```

**ספייק לא יכול להתבזבז.** הרתמה הייתה נכתבת בקומיט 1 בכל מקרה. אם הוא
זול מסבב אחד ומפיק תוצר נדרש — הסף לעשות אותו צריך להיות נמוך מאוד.

### הסייג — מה לא לספייק מוקדם

**אל תספייק דבר שהעיצוב שלו הוא השאלה הפתוחה.** לרתמה ולשער הממשק היה
ידוע מראש; שם ספייק רק מגלה עובדות. אם עוד לא הוכרע *איך* משהו יעבוד,
ספייק מוקדם **נועל עיצוב** — ואז מגנים על קוד שנכתב במקום לבחור נכון.

## 14. חלוקת העבודה מתכנן/מבצע — הסרגל מול המוצר

טענה: מה שהספייק בונה **אינו המוצר**.

```
golden-page.js   לא משנה את האפליקציה. הוא מודד אותה.
page-src.js      לא משנה את האפליקציה. הוא טוען אותה.
הקורפוס          אינו פיצ'ר. הוא אמת המידה.
```

המתכנן **כבר היום** בעלים של אמת המידה — זה מה ש-DoD הוא. הספייק לא
מזיז את הגבול; הוא כותב את ה-DoD **בשפה שרצה**. לא מבקשים ממי שנמדד
לבנות את הסרגל.

**אבל ההפרה האמיתית כן קרתה, והיא דבר אחר:** קומיטים 3–6 (העברת הקוד
עצמו) בוצעו ע"י המתכנן כי אליעזר נפל. זו עבודת מבצע. אין לערבב בין
השתיים.

**והסיכון שנשאר בגרסה הלגיטימית**: אם המתכנן בונה את השער, השער מקודד
את נקודות העיוורון שלו. כלב הוכיח את זה (§7). המשקל-הנגדי אינו "שהמתכנן
לא יבנה את השער" אלא **"מאמת עצמאי חייב לתקוף אותו"** — שורה בתדריך.

מה שנשאר למבצע כאן: ~800 שורות שזזות, כל החיווט מ-`eqChecker` לייבוא
ישיר, כל המחיקות, שתי דליפות המנוע עם בדיקות שנופלות-קודם, וחבילות
הפריסה. 9 קומיטים. הספייק היה 420 שורות.

### שלב 1 — גשש חד-פעמי ב-/tmp, ~30 שורות, נמחק אחר כך

### שלב 2 — הקובץ האמיתי, והידע נכנס כהערה

```js
    // location.protocol נדרש בפועל — רישום ה-service worker בודק אותו.
    // נמצא בהרצה, לא בקריאה. זו הסיבה שהבדל הזה נבנה בניסוי ולא בעיון.
    location: { search: "", hash: "", href: "http://localhost/",
                protocol: "http:", pathname: "/" },
```

השורה "נמצא בהרצה, לא בקריאה" היא **התיעוד היחיד שמונע מהבא בתור למחוק
את זה** כי "נראה מיותר".

```js
// const/let ברמה העליונה **אינם** נוחתים על אובייקט ה-context של vm —
// רק var והצהרות function. נמדד: ctx.A undefined עבור `const A=1`.
// 27 מ-52 הסמלים כאן מוגדרים ב-const, ולכן נדרש אפילוג מפורש.
const epilogue = "\n;" + SYMBOLS
  .map((n) => `try { this.${n} = ${n}; } catch (e) { this.${n} = undefined; }`)
  .join("\n");
```

### שלב 3 — קנרית: איך יודעים שהבדל לא בלע שגיאה

הדף עוטף **כל** קריאה למנוע ב-try/catch, ולכן `eqChecker` חסר לא
מתפוצץ — הוא מחזיר ריק בשקט.

```js
(function canary() {
  const clean = api.cleanLatex("\\boxed{x+1}");        // לא תלוי מנוע

      "\n  שתי סיבות: coeffs עצמו שבור, או ש-eqChecker חסר מה-context");
```
