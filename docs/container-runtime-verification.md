# אימות תמונת קונטיינר אחרי תיקון

⟨2026-10-05⟩

לפני verdict על שינוי בתמונת קונטיינר, קשרו בין קוד המקור, התמונה
והקונטיינר שנבדק. מניפסט שמעתיק מזהה של תמונה קיימת אינו מוכיח שהיא
נבנתה מהקוד המתוקן.

## סדר הבדיקה

1. מסרו למאמת את ה-SHA המועמד כערך מפורש. `HEAD` ב-worktree של המאמת
   יכול להצביע לבסיס של סבב קודם. רשמו את `git rev-parse HEAD` ואת מצב
   העץ שממנו בונים, ובצעו השוואות למועמד באמצעות `git show <SHA>:<path>`
   או worktree נקי באותו SHA. שינוי בקובץ שמועתק לתמונה מחייב בנייה
   מחדש ובדיקות של הנתיבים שהושפעו.
2. רשמו את image ID שהבנייה הפיקה, ובדקו שהתמונה מכילה את הקבצים
   המתוקנים. העדיפו השוואת תוכן או checksum לקבצים המועתקים; חותמת זמן
   או תג אינם תחליף להשוואה.
3. צרו מחדש את קונטיינר הניסוי מאותו image ID. בדקו את מזהה התמונה
   ב-`inspect` של הקונטיינר. בדקו mounts ו-`diff`: קובץ שמגיע מ-bind או
   תוקן בשכבת הכתיבה אינו ראיה לתכולת התמונה.
4. הפרידו בין שני ניסויים: אתחול עם בית ריק, ואתחול חוזר עם בית קיים.
   בשני, שנו מראש קובץ משתמש ובדקו שתוכנו נשמר. checksum ו-mtime של
   קובץ שלא שונה אינם מוכיחים שלא הועתק מחדש באמצעות `cp -a`.
5. להרצת תהליך מ-release קבוע, בדקו גם את קוד התהליך וגם את המפרש.
   `cwd` יכול להיות תיקיית העבודה של המשתמש. העוגנים המתאימים הם
   `/proc/<pid>/exe`, `cmdline` ו-`maps`, עם הרשאות קריאה מתאימות.
6. בדקו רצף מלא: תהליך ב-A, החלפת backend ל-B, אותו תהליך עדיין ב-A,
   תהליך חדש ב-B, וחזרה ל-A. תעדו PID ונתיבים בכל שלב. fixture יכול
   להוכיח בידוד cgroups ושרידות תהליך; הוא אינו מוכיח turn של ספק.
7. הריצו את הבדיקות הרלוונטיות על התמונה הסופית. בדוח הפרידו `pass`,
   `fail` ו-`not_run`. היעדר credentials אינו חסם לבדיקה שהבריף מתיר
   לבצע באמצעות fixture.
8. לפני הודעת המסירה, קראו שוב `git rev-parse HEAD`. קומיט שהוחלף
   ב-amend אינו ה-SHA למסירה, גם אם הופיע בהודעה קודמת.

## קבצים שמעתיקים בין עצים

checksum של עץ דורש סדר קבוע ושמות יחסיים לאותו שורש. פלט `find` לבדו
אינו מבטיח סדר. מיינו שמות עם `LC_ALL=C sort -z`, טפלו בשמות באמצעות
מפרידי NUL, והגדירו במפורש כיצד נבדקים symlinks וקבצים ריקים.
אין לפתור mismatch באמצעות מחיקת בית משתמש או ביטול בדיקת התקינות.

## תחום הניסוי

השתמשו בבתים, אינדקסים, פורטים ושמות שירות נפרדים. לפני עצירת תהליך בדיקה,
אמתו שזה ה-PID שהריצה השיקה. לאחר הניסוי, נקו את תהליכי העזר ושמרו רק
את הפריוויו שהמסירה דורשת. בדקו שהוא נשאר חי לאחר סגירת סוכני הביצוע.
