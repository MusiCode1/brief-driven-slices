# ‏ארכיטקטורת הליבה — ‏רציונל התכנון המקורי

## ‏צוות של 5 ‏סוכנים בשמות תנ"כיים

**‏מה הוחלט**: ‏הפרדת התהליך ל-5 ‏סוכנים — ‏מרדכי (planner), ‏יתרו (orchestrator),
‏אליעזר (executor), ‏אביגיל (plan-verifier), ‏כלב (runtime-verifier).

**‏למה**: ‏הבעיה המקורית — ‏build agent רגיל שמבצע תכנית **‏מ-merged ל-dev ‏בלי
‏לשאול** (5/7 ‏מ-merges אחרונים ב-voice-acp, ‏חלקם ב-45 ‏שניות ברצף). ‏הסיבה
‏המבנית: ‏האיסור על merge הוגדר רק ב-`executor.md` (`mode: subagent`), ‏אבל
‏ה-build agent **‏אינו** ‏executor — ‏הוא orchestrator בלי הוראת איסור. ‏ההפרדה
‏לתפקידים מפורשים, ‏כל אחד עם הרשאות ברורות, ‏סוגרת את הפרצה.

**‏חלופות שנדחו**:
- ‏**4 ‏מאמתים נפרדים** → ‏אוחדו ל-2: ‏אביגיל (לפני) ‏וכלב (אחרי, `mode` param).
  ‏ההפרדה האמיתית היא **‏שלב** (לפני/אחרי), ‏לא היקף. phase/light/heavy = ‏אותה
  ‏פעולה בהיקף שונה → ‏פרמטר אחד.
- ‏**להחליף את ה-build agent** → ‏נדחה. ‏הסוכנים החדשים **‏מוסיפים**, ‏לא מחליפים.

## ‏השמות התנ"כיים (‏הרציונל לכל אחד)

- **‏מרדכי** (planner) — ‏אסטרטג מגילת אסתר. ‏תכנן רב-שלבי, ‏פעל **‏דרך סוכנים**
  ‏(אסתר), ‏הציל עם שלם. ‏(נבחר על Shlomo/Yoav/Hushai — ‏היחיד שתכנן-דרך-אחרים.)
- **‏יתרו** (orchestrator) — ‏**‏המציא delegation** (שמות יח): ‏ראה שמשה נחנק,
  ‏בנה פירמידה היררכית, ‏פתר scaling. ‏(נבחר על Levi — ‏דמות פרטית עם מנגנון.)
- **‏אליעזר** (executor) — ‏עבד אברהם (בראשית כד): ‏קיבל brief מפורט, ‏הטיל unit
  ‏test (מבחן רבקה), ‏חזר ודיווח. ‏לא הגדיל ראש, ‏לא ביצע merge בעצמו.
- **‏אביגיל** (plan-verifier) — ‏עצרה את דוד **‏לפני** ‏טעות בלתי-הפיכה (1 ‏שמואל
  ‏כה). ‏plan stage — ‏לעצור פעולה הרסנית לפני ביצוע.
- **‏כלב** (runtime-verifier) — ‏המרגל שחזר ואמר **‏את האמת על מה שראה בשטח**.
  ‏runtime verification — ‏מדווח מהסביבה האמיתית.

## merge בלעדי למרדכי, ‏אחרי אישור משתמשת

**‏למה**: merge הוא **‏נקודת אי-חזרה**. ‏רק מי שרואה את ה-roadmap המלא (מרדכי +
‏המשתמשת) ‏מחליט מתי. ‏יתרו אוטומטי לא רואה תמונה שלמה — ‏גם אם slice עבר
‏verifier, ‏הוא **‏עוצר ושואל**. ‏האיסור נכנס ל-SOUL.md (לא ב-repo) ‏כדי לכסות גם
‏את ה-build agent הרגיל שיורש אותו.

## ‏ביצוע אסינכרוני ב-tmux (‏לא Task סינכרוני)

**‏למה**: ‏כלי `Task` ‏סינכרוני — ‏חוסם 30-60 ‏דק'. ‏עם 3-4 worktrees מקבילים זה
‏בלתי-נסבל. tmux + sentinel מאפשר ליתרו לא להיחסם. **‏מקביליות נדחתה בכוונה**:
‏יתרו סדרתי — ‏בלילה אין לחץ זמן, ‏מקביליות רק מסכנת (port conflicts, ‏file races).

## state מחוץ לריפו (`~/.local/state/`), ‏JSON ‏לא YAML

**‏מחוץ לריפו**: ‏אפס git noise, ‏עדכון חופשי, ‏שורד worktree removes (לעומת בריפו:
‏commits מזהמים git log + conflicts; ‏לעומת bare metadata: ‏אובד ב-clone).
**‏JSON ‏לא YAML** (ל-state.json): ‏`yq` (ה-binary) ‏לא זמין → JSON
‏נפרס ע"י json stdlib (תמיד זמין). ‏מנטרל 3 ‏באגי-פרסור (grep שביר, ‏substring
‏15/15d, ‏פרסור טבלה). trade-off: ‏פחות נעים לעריכה ידנית — ‏אבל מרדכי הוא LLM.

> **‏תיקון 2026-06-01**: ‏ההנחה המקורית כאן הייתה "**`yq` ‏ו-PyYAML לא זמינים**" — ‏זה
> ‏**‏שגוי לגבי PyYAML**. ‏אומת (`env -i /usr/bin/python3 -c "import yaml"` → 6.0.2,
> ‏ב-`/usr/lib/python3/dist-packages/`, ‏עובד גם מטיימר). ‏רק **`yq` (ה-binary)** ‏חסר.
> ‏ל-state.json ‏עדיין JSON (טוב ל-LLM); ‏אבל לדוחות-אימות (slice-2) ‏משתמשים ב-YAML
> ‏front-matter דרך PyYAML. ‏שני דברים שונים: ‏ספריית-python (PyYAML, ‏קיימת) מול binary (yq, ‏חסר).

## BLOCKED דרך קיום-קובץ, ‏לא exit code

**‏למה**: ‏בתחילה תוכנן "exit 3". ‏אביגיל (סבב 3) ‏תפסה שזה **‏בלתי-אפשרי**:
‏`opencode run` ‏תמיד מחזיר exit 0 ‏(אומת `run.ts`). ‏אליעזר הוא LLM בתוך session
‏— ‏אין לו שליטה על exit code. ‏הפתרון: ‏**‏הפוך את הסימן** — ‏קיום-הקובץ הוא הסימן.
‏כשל לוגי (typecheck/lint) ‏נתפס ע"י כלב (NO-GO), ‏לא exit code. exit≠0 ‏רק
‏לקריסות-תשתית (124 timeout / 125 crash, ‏נתפסים ב-wait-for-slice.sh).

## ‏שרשור worktrees כברירת מחדל + depends_on חובה

**‏למה**: ‏השיקול שהכריע — **‏בלילה הטוקנים לא מתחרים על שום דבר**, ‏אז "בזבוז
‏עבודה" ‏אינו שיקול. ‏slice B ‏על branch של A (לא dev), ‏שרשרת שלמה רצה בלילה.
‏מה שמאפשר בבטחה: **‏dev לא נוגעים בו כל הלילה** → ‏זריקה בטוחה לחלוטין.
`depends_on` ‏חובה בכל brief; ‏אביגיל מחזירה אם חסר (מונע slice על בסיס חסר).

## 4 ‏מצבי טיפול-כשל + discard_chain + merge-not-squash

**‏4 ‏מצבים** (מרדכי בבוקר): ‏מזג-מה-שעבד / ‏תקן-במקום / ‏זרוק-הכל / ‏מזג-הכל.
‏המצב הרביעי (**‏תקן-במקום**) ‏נוסף כי לא הכל שחור-לבן (90% ‏טוב → ‏תקן, ‏לא זרוק).
**discard_chain** ‏זורק dependents (כלפי מעלה), ‏לא dependencies — ‏A ‏ב-A→B→C
‏שבה B ‏נכשל **‏לא נזרק** (הוא dependency של B). ‏הגנת מעגל, ‏מסרב למחוק merged.
**merge-not-squash** ‏בשרשור: squash שובר ancestry → ‏כפילויות; `--no-ff` ‏מזהה
‏ancestry משותף (אביגיל סבב 2).

## ‏יתרו "טיפש ובטוח" — ‏לא מתקן, ‏לא מחליט

**‏למה**: ‏בלילה אין מי שיפקח. ‏יתרו מתעד ‏ועוצר ענפים, ‏לא מתקן/מחליט/מוחק. ‏יציב
‏> ‏אגרסיבי. ‏**‏חלופה שנדחתה (עתידי)**: ‏סוכן פותר-תקלות / "להעיר את מרדכי באמצע
‏הלילה" — ‏שובר את העיקרון ש"בלילה אף אחד לא מקבל החלטות מורכבות לבד".

## 3 ‏אופני הפעלה (Mode 1/2/3)

Mode 1 ‏(סינכרוני, ‏Task, ‏slice בודד) / Mode 2 ‏(לילי, ‏tmux, ‏עומס) / Mode 3
‏(ישיר מהמשתמשת, ‏לגיטימי אך לא ראשי — ‏slice ‏ההוצאה עצמו רץ ב-Mode 3).

## 4 ‏סבבי אביגיל על מסמך התכנון (‏השיטה על עצמה)

‏הפעלה רקורסיבית. track record 100% hitrate: ‏סבב 1 (env scrub + PATH), ‏סבב 2
‏(yq/PyYAML לא קיימים → ‏JSON), ‏סבב 3 (exit 3 ‏בלתי-אפשרי → ‏file-existence + 4
‏הקשחות), ‏סבב 4 (2 ‏שרידי exit 3). ‏הליבה (הרשאות, ‏שרשור, ‏4 ‏מצבי כשל, "dev
‏לא נוגעים") ‏עמדה איתנה. ‏מה שנתפס היה תמיד ברמת המימוש — ‏טעות-המלכה (הנחה
‏לא-מאומתת על API/סביבה).

## 2026-05-30 — ‏תיקון שיטה: decisions של פרויקט שייכות לריפו הפרויקט

### ‏הבאג בשיטה

‏ההגדרה המקורית ב-mordechai.md אמרה ש-decisions של **‏כל פרויקט** נכתבות לריפו
‏השיטה (`brief-driven-slices/main/docs/decisions/<project>.md`). ‏זה שגוי:
‏הרציונל של החלטה ארכיטקטונית הוא **‏חלק בלתי-נפרד מהפרויקט**. ‏מי שעושה clone
‏לפרויקט בעוד שנה צריך להבין *‏למה* ‏הקוד ככה — ‏ליד הקוד, ‏לא בריפו מתודולוגיה
‏נפרד שאולי לא קיים אצלו. ‏קבירת ה"למה" ‏בריפו חיצוני שוברת לוקאליות, ‏מקשה על
‏clone/שיתוף, ‏ומפזרת ידע.

### ‏ההכרעה

- **‏decisions → ‏ריפו הפרויקט** (`<project-repo>/docs/decisions/`), ‏ליד הקוד.
- **‏reports → ‏נשארים בריפו השיטה** (מרכזי).

### ‏למה decisions ו-reports מתפצלים (‏נראים דומים, ‏שונים בתכלית)

- **‏decisions** = ‏ידע ל**‏קוראי הפרויקט** ("למה הקוד ככה"). ‏ערך **‏לוקאלי** → ‏פרויקט.
- **‏reports** = ‏חומר-גלם ל**‏זיקוק המתודולוגיה** (טעויות חוזרות בכל הפרויקטים).
  ‏ערך **‏גלובלי-מצטבר** → ‏שיטה. ‏(זו הצדקת ה-brief השני — ‏זיקוק חוצה-פרויקטי.)

## 2026-06-01 — slice-2-distillation: שכבת הזיקוק

### ‏המנגנון המשולב (כמותי → איכותני → branch → merge-אנושי)

**מה הוחלט**:
- `distill.py` כמותי-בלבד (ספירה, hitrate, delta, traceability) → `<date>-data.json`
- מרדכי-אוטומטי קורא ה-data ומפרש → `<date>-report.md` + עדכון קטלוגים
- תוצר ב-**branch `bds-distill-<date>`** — **לא main**
- **merge תמיד אנושי** — מרדכי בבוקר סוקר

**הרציונל**: ה-merge הוא נקודת אי-חזרה (עיקרון בסיסי). הפרדת כמותי/איכותני מסייעת:
הסקריפט מספק facts (מה הצטבר), המודל מספק פרשנות (מה זה אומר).

**3 הגנות נגד merge אוטומטי**:
1. פרומפט מרדכי-אוטומטי אוסר merge מפורשות
2. worktree של branch נפרד — merge ל-main דורש פעולה מפורשת
3. SOUL.md אוסר merge בלי אישור משתמשת

**חלופות שנדחו**:
- "merge אוטומטי אם כלב GO" — נדחה. merge = נקודת אי-חזרה, תמיד אנושי.
- "distill.py כותב הכל (כולל פרשנות)" — נדחה. סקריפט לא מפרש, לא מנסח כללים.

### פורמט דוח-אימות MD-front-matter (במקום JSON טהור)

**מה הוחלט**:
דוחות שאביגיל וכלב כותבים = קובץ `.md` עם YAML front-matter + גוף MD מלא.
מחליף את ה-JSON הטהור (backward-compat נשמר — `load_reports` dual-format).

**הרציונל**: ה-MD המפורט שמאמת כותב ב-Task result **נעלם** כשהסשן נסגר.
`findings:[]` לא מבדיל "נבדק היטב" מ"כמעט לא נבדק". הפורמט החדש שומר הכל:
- YAML front-matter = data מובנה (פרסיבלי ע"י `distill.py` + yaml.safe_load)
- גוף MD = הדוח המלא (נגיש לאדם, לא נאבד)
- מקור-אמת יחיד (לא שני קבצים)

**הסיכון**: front-matter שבור (summary עם `:` לא-מצוטט) → yaml.safe_load זורק.
מיטיגציה: (1) parse_report_file סלחני — None+warn; (2) הוראת ציטוט מפורשת ב-agents.

### שני gates (plan-gate + runtime-gate)

**מה הוחלט**:
- **plan-gate**: `plan_verified=true` רק כש-אביגיל verdict=**READY**
- **runtime-gate**: merge רק כש-כלב verdict=**GO** (או דחייה מפורשת+מתועדת+מאושרת)

**הרציונל**: עד slice זה, ה-gates היו אמורים אבל לא מנוסחים כתנאי מפורש.
היה אפשרי ל-מרדכי לסמן plan-verified על USABLE-AFTER-FIX (בלי לתקן).
ולמזג על PARTIAL בלי תיעוד. אלה gaps בחוזה שצריך לסגור.

runtime-gate **לא חוסם מוחלט** — דחיית-bug מותרת אם מתועדת ב-decisions + מאושרת.
זה ה-tradeoff: לא לחסום release על bug קטן, אבל לא לאבד track.
